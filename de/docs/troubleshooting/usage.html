Nutzungs-Fehlerbehebung

Probleme mit der WiFi-Konnektivität​

  • Halten Sie Console und Scale auf Abstand, um Störungen zu vermeiden, die Folgendes verursachen können:
    • Wiederholte Verbindungsabbrüche der Scale zur Console
    • Verbindungsprobleme zwischen Console und Drucker, die langsame Reaktionen verursachen
    • Andere verwandte Probleme

Probleme mit der Druckerverbindung​

Bei P1/A1-Druckern gibt es eine Begrenzung für die Anzahl gleichzeitiger Verbindungen. Wenn mehrere Integrationen (z. B. HA, Panda, XTouch) zusammen mit mehreren Instanzen von Bambu Studio laufen, kann SpoolEase möglicherweise keine Verbindung herstellen.

  • Versuchen Sie, andere Integrationen zu beenden und zusätzliche Bambu-Studio-Instanzen zu schließen, um zu prüfen, ob das Problem dadurch behoben wird. Verwalten Sie anschließend die Anzahl aktiver Integrationen entsprechend.

Unzuverlässiges Kodieren​

  • Verwenden Sie ein hochwertiges, stabiles und ausreichend starkes USB-Netzteil.
  • Probieren Sie ein anderes USB-Kabel aus.
  • Legen Sie das Tag nicht direkt auf den PN532 - halten Sie es für zuverlässiges Kodieren etwa 1 cm entfernt.
  • Stellen Sie sicher, dass Sie ein kompatibles Tag verwenden: nur NTAG215. Mifare wird zwar für die normale Nutzung unterstützt, ist derzeit aber nicht für das Kodieren des virtuellen Etiketts unterstützt. FeliCa-Tags werden gar nicht unterstützt.

Langsame Benutzeroberfläche​

Wenn die Benutzeroberfläche langsam wirkt und träge reagiert oder SpoolEase verzögert auf Druckeraktivitäten reagiert, prüfen Sie, ob Sie in der SpoolEase Console Web Config erweiterte Drucker-Logs aktiviert haben.

SpoolEase hängt alle paar Stunden oder funktioniert nicht mehr​

Versuchen Sie es mit einer besseren Stromversorgung.

SpoolEase verfolgt den Filamentverbrauch nicht​

  • SpoolEase muss beim Start des Drucks bereits laufen. Wenn es erst danach gestartet wird, kann der Filamentverbrauch nicht verfolgt werden.
  • SpoolEase kann den Filamentverbrauch nicht verfolgen, wenn die Druckdatei aus dem internen Speicher des Druckers geladen wird. Dazu gehören:
    1. Das Drucken vorinstallierter Modelle, die mit dem Drucker geliefert werden
    2. Die Verwendung des Buttons Print Again auf dem Druckerdisplay nach Abschluss eines Drucks
    3. Das erneute Drucken eines zuvor gedruckten Modells aus dem internen Speicher des Druckers
  • Prüfen Sie zuerst im Feld „Consumed Since Loaded“ der Slot-Informationen, ob der Verbrauch verfolgt wird. Damit sich der Filamentverbrauch in der Spule selbst widerspiegelt, müssen bestimmte Informationen für die Spule ausgefüllt sein. Weitere Informationen finden Sie unter Spulengewichtsverfolgung.
  • Prüfen Sie, ob in Ihrem Drucker eine SD-Karte bzw. ein USB-Stick installiert ist. Das ist erforderlich, wenn sich der Drucker im Dev Mode befindet oder so eingestellt ist, dass Druckdateien immer per FTP abgerufen werden.
  • Prüfen Sie, ob der USB-Stick korrekt funktioniert. Der Drucker kann auch ohne USB-Stick völlig normal funktionieren, und bei bestimmten Fehlern arbeitet der Drucker einfach ohne ihn weiter. Ein solcher Fehler verhindert jedoch, dass SpoolEase den Filamentverbrauch verfolgt.
  • Prüfen Sie, ob Ihr Drucker so konfiguriert ist, dass gesendete Dateien auf externem Speicher abgelegt werden („Store Sent Files on External Memory“, verfügbar unter „Print Options“ auf dem Druckerdisplay).
